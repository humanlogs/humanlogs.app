Coding people and documents works today, from the speaker badge, the document menu or the study coding board, see [Codebooks](/docs/coding/codebooks). **All three are mouse gestures: there are no coding shortcuts yet.**

## What already helps

Everything in the editor. Moving through the transcript, playing the audio while you read, selecting a passage: the shortcuts in [Keyboard shortcuts](/docs/transcribe/keyboard-shortcuts) are the ones you use to get to what you are about to code.

Custom shortcuts are worth knowing about too: you can bind a key to a piece of text, which is how some people mark passages by convention (`[theme:trust]`) while waiting for passage coding. Those marks are text, not data, so treat it as a stopgap rather than a system.

## What is planned

Coding is only fast when a code is one keystroke away. The intent is:

- A number key per code in the active codebook, applied to the current selection or the current speaker.
- Repeat-last-code, for the long stretches where one theme dominates.
- Undo that removes a code without touching the transcript.

Nothing above is final. If you code for a living and have opinions about what those keys should be, the feedback button in the app reaches us directly.
